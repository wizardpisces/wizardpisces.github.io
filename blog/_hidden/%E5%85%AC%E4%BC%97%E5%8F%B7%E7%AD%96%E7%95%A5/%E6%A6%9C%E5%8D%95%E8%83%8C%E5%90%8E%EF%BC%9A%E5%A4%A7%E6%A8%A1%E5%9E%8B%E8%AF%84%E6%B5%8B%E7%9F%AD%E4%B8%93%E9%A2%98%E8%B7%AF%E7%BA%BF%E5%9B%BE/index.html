榜单背后：大模型评测短专题路线图

榜单背后：大模型评测短专题路线图

定位

这是一个阶段性短专题，不新增为顶级系列。

评测会同时穿过模型能力、Agent 工作流和实际工程选择。每篇仍按核心问题归入“模型为什么这样设计”或“从一句 Prompt 到可靠 Agent”，本专题只提供一条共同的追问路径：

这个分数到底测到了什么，又漏掉了什么？

读者承诺

每次模型发布都会带来大量分数、排名和“领先多少”的结论。本专题不逐项介绍 Benchmark，而是从读者已经看见的榜单矛盾进入，解释：

  • 不同分数为什么不能直接比较。
  • 一次成绩里混入了哪些模型之外的因素。
  • 评分器凭什么宣布任务成功。
  • 公开榜单为什么不能替代真实业务评测。

读者最终应获得一套判断模型新闻和工程选型的方法，而不是记住一组评测名称。

边界

不做：

  • Benchmark 名词百科。
  • 新模型发布数据汇总。
  • 只按排行榜复述谁超过了谁。
  • 脱离具体任务讨论抽象的“模型智力”。

只有当一个评测结果暴露了明确的反差、误解或现实决策问题时，才值得成篇。

问题路径

为什么同一个模型在不同榜单上提升差异巨大
        ↓
一次成绩测到的究竟只是模型，还是整个运行系统
        ↓
评分器如何定义“任务已经完成”
        ↓
模型越来越强后，旧评测为什么失去区分度
        ↓
公共榜单怎样转化成自己的选型与验收标准

首批文章

1. GPT-6 Astra 为什么有些榜单只涨 1 分，有些却涨了 40 分？

  • 入口：同一张发布页上的提升幅度差异巨大。
  • 核心问题：不同评测究竟卡住了模型的哪种能力？
  • 带走判断：涨幅取决于剩余提分空间、任务要求和分数汇总方式；长任务的乘法例子解释可能机制，不直接证明 Astra 的提升原因。
  • 主归属：模型为什么这样设计。
  • 状态：已有草稿。

2. 同一个模型，为什么换个 Agent 框架就能多修几十个 Bug？

  • 入口：模型不变，换一套 Harness 或 Agent 框架，软件工程榜单就可能明显变化。
  • 核心问题：榜单成绩中有多少来自模型，有多少来自工具、提示词、上下文管理和重试策略？
  • 带走判断：复杂任务评测测到的是一个运行系统，不是裸模型。
  • 主归属：从一句 Prompt 到可靠 Agent。
  • 与旧文关系：承接《DeepSeek 为什么也开始造 Harness？》，但重点从 Harness 的价值转向评测归因。
  • 状态：已有草稿。

3. AI 写的测试全通过了，为什么 Bug 还在？

  • 入口：Agent 提交修改，测试全部通过，真实问题仍可能存在。
  • 核心问题：评分器凭什么判断任务成功，它没有检查到什么？
  • 带走判断：测试通过只能证明满足所检查的条件；预期必须依据需求，不能照着实现反推。用原故障复现和原有行为检查验证修复。
  • 主归属：从一句 Prompt 到可靠 Agent。
  • 与旧文关系：与《写 Skill 的 Skill，怎么知道自己写对了？》交叉，但聚焦软件任务中的成功判定。
  • 与上一篇递进：从“哪套系统做出了补丁”继续追问“验收凭什么判补丁正确”；沿用用户名含空格的示例。
  • 状态：已有草稿。

4. 模型越来越强，为什么老榜单反而越来越没用了？

  • 入口：多个前沿模型都接近满分，榜单仍在给它们排出精确名次。
  • 核心问题：当评测饱和、题目泄漏或模型针对榜单优化后，分数还剩多少区分力？
  • 带走判断：评测不是固定尺子；被测对象变化后，尺子的难度、覆盖面和评分方式也必须变化。
  • 主归属：模型为什么这样设计。
  • 与旧文关系：可引用《当排行榜开始“训练”大模型》，但本篇解释评测为何失效，不重复讨论榜单如何反向塑造模型。

5. 榜单第一的模型，为什么到了你的项目里不一定最好用？

  • 入口：公共榜单领先的模型，在真实项目中可能更慢、更贵，或者需要更多人工检查。
  • 核心问题：公共评测怎样转化成自己的选型依据？
  • 带走判断：最终要评估的是一次成功任务的质量、成本、延迟、重试和人工介入，而不是模型的单项排名。
  • 主归属：从一句 Prompt 到可靠 Agent。
  • 与旧文关系：承接《又便宜又强，就能“斩杀”其他大模型吗？》，从多指标选择继续走向本地评测。

使用方式

  • 有模型发布热点时，优先寻找它暴露了哪个评测问题，不为追热点重复写发布总结。
  • 五篇存在认知递进，但不要求连续发布；每篇必须脱离前文独立成立。
  • 写完第五篇后再决定是否继续。若没有新的评测矛盾，只保留为短专题，不扩成课程。
