Agent 改进工作空间：上下文设计与反馈采集

核心

Skill Creator Workspace 将任务、执行过程、环境反馈和人工修订组织起来，让 Creator 看清哪里失败、如何修正、结果是否改善，再结合工程已有经验生成候选 Skill。

经验提炼的依据需要从“模型认为自己的选择合理”，转向“这次选择在环境中产生了什么结果”。只记录选择理由和最终总结，很难找到改进方向；保留真实输出、验收依据和反馈驱动的重试，才能看清哪些路径反复失败、哪些调整改善了结果。

上下文范围

上下文 功能 帮助回答什么 举个例子
原始任务、验收目标与约束 还原 Case 应该完成什么，什么才算成功， 还原 figma ，验证截图对比
各轮结果、人工评论和修订 做 reward 人指出了什么，Agent 实际改变了什么 交互节点（比如嵌入的 codex 交互）
环境验证与反馈重试摘要 核实 reward 哪些尝试失败，哪些调整产生了可观察改善， 跑 test Case
完整轨迹与实际产物 溯源 摘要是否准确，关键细节能否回查，辅助溯源 比如 langfuse.log
工程状态与既有 Skills 验证 skill 当时有什么能力和约束，已有经验为何未覆盖 conventions

上下文按任务和结果版本关联，保留执行时的工程与 Skill 状态。完整轨迹提供事实，验证摘要定位优化点，工程和已有 Skills 提供约束；Creator 按需读取相关材料。

两个闭环

任务内，通过实际执行和反馈修正结果：

Plan / Coding → 环境结果 → 检查或人工评论 → 修改 → 再次验证

任务后，人工驱动经验提炼：

上述上下文 → Skill Creator Workspace → 候选经验
→ 人工 Review → 新 Case 验证 → 更新下一次任务可用的 Skill

保留每轮结果、评论、自检和实际修改。人工不只是批准候选，还会指出问题、纠正归因、补充工程约束和修改策略。这些反馈与对应修订同样进入 Workspace，帮助 Creator 理解经验为何被采纳、调整或否定。

随着这些过程积累，可以进一步提炼 Creator 自身的分析经验：怎样定位问题、选择证据、划定适用范围。由人工指导经验提炼，再从指导过程改进 Creator。

如何采集可优化的轨迹

通过已有 MCP，重点采集关键环境验证中的上下文：

当前情况与输入 → 验证目标 → 实际输出与判定 → 具体失败点 → 根据反馈做过的调整 → 再次验证。

重点关注反复失败、无效重试、人工纠正和最终改善，也保留首次成功作为对照。每次判定保留标准、来源和证据入口，便于回查实际输出与产物。

验证摘要相当于完整轨迹中的优化点索引：先帮助 Creator 找到值得复盘的失败与修正片段，再回查当时的输入、工具输出、代码变化和评判依据。这样既能聚焦问题，又能核对摘要是否遗漏了影响结果的条件。

测试、接口运行、Mock、浏览器、Native 观察和人工检查都可以提供反馈。RN Screenshot Perception Layer 提供其中的 Native 运行上下文。

Workspace 如何服务 Agent

Creator 沿反馈定位相关轨迹，检查代码与产物，比较各轮结果，并结合已有 Skills 自主分析：该改进的是工程信息、工具能力、验证方式，还是可复用的执行策略。

有可复用经验时，优先更新适用的既有 Skill；候选经过人工 Review，再用新的 Case 验证效果。

例如，标题栏初版验证失败，调整样式后仍失败，更换组件后通过。摘要定位这三轮尝试，Creator 再查完整轨迹与工程用法，判断问题来自组件能力、布局处理还是信息缺失，并检查验证条件是否一致。由此提炼有依据的选型与验证策略，而不只是把最后一次修改写成经验。

验证方式

先用真实 Case 检查上下文能否支持失败定位、修正核查和经验提炼，再通过新 Case 的成功率、修正轮数和成本判断效果，持续调整采集重点与 Workspace。
