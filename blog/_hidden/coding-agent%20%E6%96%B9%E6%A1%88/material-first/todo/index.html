→ 现有流程节点
→ Codex
→ 可运行 RN 页面
→ 人工验收

后续灵感与研究方向

以下内容不是当前阶段 1 的阻塞项，但作为后续优化 Agent 路径的重要指导保留。

Task Brief

Task Brief：探索如何从完整 PRD 中提取 RN 页面任务，形成 Schema 与 Direct 路径可以共用的轻量输入。

可能的最小形态：

页面目标
页面入口与业务场景
必须展示和交互的内容
不能破坏的业务约束
设计稿或截图
验收条件

可能的推进策略：

  1. 当前继续复用现有 PRD、TD 和 Schema 流程完成页面上线；
  2. 从真实任务中手工整理一份最小 Task Brief，同时提供给 Schema 与 Direct；
  3. 只有它能减少需求误解或人工补充时，才进一步研究自动提取和结构化。

按需视觉定位与素材提取

Visual Inspect：Agent 看不准位置或需要原图素材时，再按自然语言描述查询目标区域。

可能的形态：

inspect_visual_target

v0 输入：原始截图 + targetDescription + Agent 判断的 bbox
v0 输出：pixel/normalized bbox + croppedImage + annotatedImage
后续：按真实 Case 判断是否接入自动视觉定位模型

可能的推进策略：

  1. 默认仍让 Codex 直接看原始截图；
  2. 只在元素定位或素材识别不稳定的真实案例中调用 Visual Inspect；
  3. 先用 v0 外显并复核 Agent 使用的坐标，记录坐标系疑虑；
  4. 只有真实 Case 证明 Agent BBox 不够稳定，才接入自动定位模型。

理论基础参考《模型能叫出按钮的名字，为什么指不准它在哪里？》。

Native Screenshot Feedback

Screenshot Preview：页面生成后，按需取得真实 Native 截图并返回 Agent，形成实现结果反馈。

可能的推进策略：

  1. 阶段 1 先由人启动 App、进入页面并提供截图；
  2. 固定页面入口、等待条件和截图方式后，再封装 screenshot_preview；
  3. 对比有无截图反馈时的最终验收、调整轮次和执行成本；
  4. 自动进入页面、视觉 Diff 和功能断言按真实失败逐步补充，不一次做全。

Agent 执行轨迹优化

执行轨迹：分别记录原始过程、阶段状态、最终结果和外部评分，用于定位 Agent 为什么成功或失败。

可能的形态：

Langfuse Raw Trace
→ Run Decision Events
→ Final Execution Report
→ Result Score

可能的推进策略：

  1. 先保证 Langfuse 能记录真实模型调用和工具调用；
  2. 再用少量 Decision Events 补充 uncertainty / tool_intent / tool_outcome / decision；只有工具结果真正影响行动时才记录 outcome；
  3. submit_execution_report 只提交最终状态和证据，由基础设施按 taskId 聚合完整 Run；
  4. 人工验收后再分析成功与失败样本，判断 Task Brief、Material 或 Tool 是否真正产生增益。

Material 演进

Material：先用最少信息帮助 Agent 找组件，遇到真实召回问题后再增加字段。

可能的演进形态：

组件名称、描述、关键词、导入路径
→ Fixture 与 Native 展示
→ 组件截图和视觉特征
→ 更复杂的检索或视觉召回

可能的推进策略：

  1. 先用最小 Metadata 和 Fixture 支持组件查找与正确引用；
  2. 记录找不到、找错和不会使用组件的真实案例；
  3. 根据失败原因分别补充关键词、示例参数、截图或视觉特征；
  4. 只有简单查询无法满足时，才引入更复杂的索引和召回方案。

页面逻辑的 Golden Path

Golden Path：当 Material 能解决组件复用，却无法约束复杂页面逻辑时，为 Agent 提供一个经过验证的同类实现参考。

可能的推进策略：

  1. 只有真实页面出现代码组织不稳定时才触发；
  2. 人工选择一个同领域、同类型的优秀页面作为 Golden Example；
  3. 记录参考源码、必须约束和验证方式，与 Baseline 做单变量比较；
  4. 验证有效后，将结论交给独立的工程复用方案继续沉淀，不在 RN TODO 中建设通用平台。

完整方案见《AI Engineering Golden Path：面向 Agent 的工程复用机制》。
