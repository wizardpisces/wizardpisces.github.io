评估世界萃取：与 Skill 协同演进的验证机制

评估世界萃取：与 Skill 协同演进的验证机制

背景与目标

任务执行留下行动、产物、环境反馈和人工修正。这些材料可以用于提炼 Skill，也可以用于恢复任务条件、构造验收场景，检验后续方法是否有效。

如果只保留 Skill，原来的问题和验收条件会逐渐丢失；如果同时保留能够重新执行与评价的环境，每次方法修订就有了可比较的依据。

本方案从同一次任务中萃取两类产物：Skill 沉淀怎样完成任务，评估世界（Env）沉淀任务在什么条件下发生、Agent 可以怎样交互，以及结果如何被评价。两类产物通过实际使用共同演进。

整体机制

任务目标、执行轨迹、产物与人工反馈
                  ↓
          同一个分析工作空间
           ↙             ↘
Skill Creator         Env Creator
提炼执行方法           萃取评估世界
           ↘             ↙
         Agent 采用 Skill，在 Env 中执行
                  ↓
         行为、结果、评价与修正
           ↙             ↘
       修订 Skill       完善 Env

人工先确认候选 Skill 的内容与适用范围，Env Creator 据此选择相关任务片段、恢复执行条件并构造评价。Skill 的实际效果通过环境中的执行结果检验。

评估世界包含什么

部分 内容与作用
初始状态 恢复任务开始时的代码或文档、相关数据与配置
交互条件 提供可操作对象、工具、依赖服务，以及必要的 Fixture 或 Mock
任务目标 保留原始要求、约束和允许变化的范围
评价机制 定义检查方式、所需证据、人工验收条件及已知评价边界

Env 应允许 Agent 根据行动获得新的环境响应，并选择不同的解决路径。任务目标和验收条件来自需求、工程约束与人工确认；候选 Skill 是接受检验的方法。

Env Creator 如何萃取环境

从问题范围恢复执行条件

围绕候选 Skill 所解决的问题，选择相关任务、失败与修正片段，提取执行所需的最小条件。

代码任务恢复起点 Commit、相关未提交改动、依赖和测试数据；文档任务恢复原文、修改要求、人工评论及前后 diff。最终实现和修改 diff 作为评价参考，保留产生这些变化的要求与理由。

起点与关键过程证据需要在原任务执行时保存。复盘阶段检查材料是否充分，标出无法恢复的依赖和条件，供人工决定补证或缩小评估范围。

构造任务入口与评价方式

Env Creator 将原始要求整理为可再次交给 Agent 的任务，配置相关工具和数据，并从原有验收中提取检查项。

执行侧获得任务、起点与必要上下文；评价侧保留参考结果、失败证据和检查依据。已知修复过程用于分析与评价，避免将来源任务的完整答案直接提供给待测 Agent。

校验环境本身

生成的 Env 需要接受人工 Review 和样本校验：

已知满足要求的结果 → 能够识别其有效性
已知违反要求的结果 → 能够发现对应失败
不同实现的合法结果 → 能够按相同要求评价

例如，标题栏 Env 应能发现回调缺失或间距不符，也应接受满足要求的另一种实现。校验结果暴露任务条件、观察能力或评价标准的缺口，再反馈给 Env Creator 修订。

Skill 与 Env 如何协同演进

两者都可以变化，但每次比较固定相应的对象：

验证 Skill：
固定 Env → 比较旧 Skill 与候选 Skill 的行为和结果

验证 Env：
固定参考样本 → 检查新 Env 的恢复能力与评价表现
            → 必要时重新评估已有 Skills

环境变化保留原因与影响范围。验收标准改变后，新旧结果分别对应各自条件；比较同一 Skill 的改进时，使用一致的环境和标准。

从 Env Creator 到 Meta-env-creator

Env Creator 负责具体环境的萃取与修订。Meta-env-creator 负责从反复出现的环境问题中，改进取证、恢复、场景构造和评价校验的方法。

某个 Env 遗漏必要数据 → 补齐该环境

多个 Env 反复遗漏执行条件
  → 分析萃取方法的缺口
  → 修订 Env Creator 的指导或工具
  → 在独立任务中验证新方法

输入包括环境构建过程、恢复失败、错误判定、人工纠正，以及后续 Skill 的应用结果。人工审核生成方法的变化，检查是否减少遗漏和误判、是否增加恢复成本。

补充新场景扩展的是评估覆盖；改进生成场景与评价的方法，才进入 meta 层。该机制作为后续探索，先保留相应过程与反馈。

初步验证范围

初版围绕一个真实任务问题，验证环境萃取与方法评估能否连接起来：

  • 能否恢复任务起点，并让 Agent 重新开展交互。
  • 能否依据原始要求评价已知成功、失败及合法替代结果。
  • 能否在同一 Env 中比较候选 Skill，回查行为、结果与证据。
  • 新发现的问题能否反馈为 Skill 修订、环境补充或明确的证据缺口。

先验证这条闭环，再根据恢复成本、评价可靠性和场景复用情况，判断环境生成与 meta 层自动化的投入。
