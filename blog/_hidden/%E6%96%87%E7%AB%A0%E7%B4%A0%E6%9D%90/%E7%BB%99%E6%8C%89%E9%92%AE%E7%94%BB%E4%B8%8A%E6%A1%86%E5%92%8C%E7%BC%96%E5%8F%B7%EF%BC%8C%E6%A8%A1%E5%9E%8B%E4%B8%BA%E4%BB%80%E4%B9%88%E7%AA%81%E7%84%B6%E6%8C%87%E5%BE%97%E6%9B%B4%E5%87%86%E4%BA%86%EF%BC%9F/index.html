给按钮画上框和编号，模型为什么突然指得更准了？

你让一个操作电脑的 Agent 点击登录按钮。

它看懂了页面，也回答对了目标：

点击下方蓝色的“登录”按钮。

可真正执行时，鼠标却落在密码输入框的边缘。

模型明明知道要点哪个按钮，为什么一报坐标就容易偏？

现在换一种做法。先在截图里的每个可操作区域外面画框，再标上编号：

┌────────────────────┐
│ [1] 手机号输入框    │
├────────────────────┤
│ [2] 密码输入框      │
├────────────────────┤
│ [3]     登录        │
└────────────────────┘

不再问模型“登录按钮的坐标是多少”，而是问：

应该操作哪个编号？

模型回答：

3

程序再查出编号 3 对应的区域，点击它的中心。按钮还是那个按钮，模型也没有更换，为什么加上框和编号以后，定位突然变准了？

报坐标和选编号，不是同一道题

直接报坐标时，模型需要完成一连串判断：

认出登录按钮
→ 判断它在截图中的精确边界
→ 换算到坐标系
→ 生成 x、y 数字

假设截图宽 1080、高 1920，模型最后要从大量可能的坐标中给出一组数字。边界稍微理解错一点，坐标原点或缩放比例再有一点偏差，鼠标就可能落到按钮外面。

《模型能叫出按钮的名字，为什么指不准它在哪里？》解释了这个缺口：认出“这是什么”，允许位置和大小发生变化；指出“它在哪里”，却必须保留精确边界。

编号没有让模型突然获得更精细的像素感。它改变了模型要回答的问题：

原来的任务：
登录按钮 → 生成一组坐标

现在的任务：
登录按钮 → 在 [1] [2] [3] 中选择一个编号

模型不再从整张截图里直接构造连续坐标，只需要在有限候选项里做选择。

精确位置其实已经提前藏在框里

这些框不是语言模型凭空画出来的。

系统会先运行一个候选区域生成器，把截图拆成一组可能被操作的区域。不同场景可以使用不同方法：

文字和输入框
→ OCR 或界面元素检测器

图标和按钮
→ 可交互区域检测器

普通图片中的物体
→ 分割模型生成 Mask

例如，SAM 这类分割模型可以为普通图片提出区域；面向图形界面的 OmniParser 则训练了可交互图标检测器，并用描述模型补充每个区域的功能语义。它们不是同一条固定流水线，只是在不同场景里承担“先把候选区域找出来”的职责。

系统同时保存一张映射表：

[1] → 手机号输入框 → [90, 180, 990, 300]
[2] → 密码输入框   → [90, 330, 990, 450]
[3] → 登录按钮     → [90, 500, 990, 620]

随后，它把编号画回截图，让模型能够在视觉区域和文字编号之间建立关系。

这种给候选区域添加可引用标记的方法，通常叫 Set-of-Mark。相关研究会先用框、Mask 或其他方式划出区域，再覆盖数字或字母，让多模态模型直接用标记指向目标。

现在，精确坐标来自候选框。语言模型负责的是：

“登录按钮”
→ 对应 [3]

程序负责的是：

[3]
→ 查表得到边界
→ 计算点击位置

看起来是模型指得更准了，实际上是系统把“理解目标”和“保存精确位置”拆给了更适合的部件。

编号把空间问题变成了选择题

有了编号，截图中的区域获得了可以直接出现在回答里的名字。模型可以把“页面下方、蓝色矩形、中间写着登录”对应到 [3]，不必再把这份空间判断翻译成两个坐标数字。

Set-of-Mark 研究发现，给图片区域加入标记，可以改善多模态模型在多类视觉定位任务上的表现。OmniParser 的实验还说明，光有编号未必够；补上区域里的文字或图标含义，模型更容易把操作意图分配到正确编号。

编号在模型和屏幕之间增加了一个共同对象：视觉工具保存 [3] 的边界，语言模型选择 [3]，执行器再点击 [3] 对应的位置。

如果候选框错了，编号也救不回来

再让登录页运行一次。假设候选区域生成器把按钮拆成了两块：

[3] → “登录”两个字
[4] → 蓝色按钮背景

模型可能正确理解“要点击登录按钮”，却不知道应该选择文字还是背景。更糟的是，如果检测器根本没有框出登录按钮，候选列表里就不存在正确答案。

密集页面还会出现另一个问题：编号太多，标记可能遮住原本的文字和图标。区域彼此重叠时，点击框的中心也不一定是安全的操作点。

所以这套方案只是移动了误差的位置：

直接报坐标
→ 误差主要在模型的空间判断和数字生成

先画框再编号
→ 误差主要在候选区域是否完整、边界是否正确
  以及模型有没有选对编号

它没有消灭定位问题，而是把一个开放的坐标生成问题，改造成了候选区域生成加编号选择的问题。

最后，让登录按钮再走一次

登录页截图
    ↓
检测或分割出候选区域
    ↓
保存区域边界，画上编号
    ↓
模型选择 [3]
    ↓
程序查表并点击 [3]

给按钮加框和编号以后，模型之所以指得更准，不是因为编号提高了它的视觉分辨率。

精确位置已经由前面的视觉工具保存下来。模型只需要在几个被明确标出的对象中选出目标，再由程序把编号还原成坐标。
