Agent 反复读长上下文，DeepSeek Flash 如何加速？

Coding Agent 修一个 Bug，要读文件、运行测试、查看报错，再继续修改。它生成的指令可能很短，工具返回的代码和日志却很长：

模型生成工具调用
↓
工具返回一大段内容
↓
模型处理新内容，再决定下一步
↓
更多内容进入上下文

你看它半天没动静，可能是在生成答案，也可能还在处理刚收到的材料，或保存、读取前面的计算结果。

DeepSeek-V4.1-Flash 就在这些地方省开销：减少处理新输入的计算，缩小历史缓存。其中一项改动，是把 40 个 Transformer Block 分成前后各 20 个。

缓存里没有的，还是得先算

假设 Coding Agent 已经读过一段 10000 个 token 的上下文，接着调用工具，收到 2000 个新 token：

旧的 10000 个 → 已有 KV，直接复用
新的 2000 个 → 没有 KV，首次计算

工具结果刚刚返回，缓存里还没有。模型得先处理这 2000 个 token，把算出的结果存下来，后面回答时才能直接读取。

这就是 KV Cache：把具体输入算出的 K、V 存下来，后面直接读取，免去重复计算。

模型先处理这批输入、准备好 KV 的过程，叫 Prefill。随后逐个生成新 token，叫 Decode。

有了 KV Cache，旧内容不用再算一遍。但新来的内容，或者没命中缓存的内容，仍要先算。新架构想省下的，就是这部分计算。

为什么首次计算要经过那么多层？

每个 token 进入模型后，先表示成一串数字，可以把它看成一张数字卡片。在普通 Decoder-only 模型里，卡片会这样往下传：

输入 token → 数字卡片
↓
Block 1
  多头 Attention：读取其他位置的信息
  FFN：继续加工当前卡片
↓
Block 2：接着加工上一层的结果
↓
……
↓
Block 40
↓
输出头：得到下一 token 的概率

一个 Block 包含 Attention、前馈网络 FFN 等计算，多个 Block 一层层接起来。Attention 的多个头可以在同一层里并行读取信息，但后一个 Block 得等前一个加工完卡片，才能接着算。

Attention 读取前文时，会从卡片算出 Q、K、V：

Q：这次要找什么
K：是否匹配这个查询
V：被读取时，提供什么内容

生成 Q、K、V 所用的权重，是训练得到的参数；KV 则是用这些权重处理具体输入后算出的结果。换一份输入，KV 会变，权重不会跟着变。

每层都从传到这一层的卡片生成 KV。想拿到很深一层的 KV，就得先让卡片经过前面各层，一层层算到这里。

让深层 KV 换一个来源

因果编码器-解码器（Causal Encoder-Decoder，CED）让后半段的全局 KV 不用再这样一层层等。

前 20 个 Block 先处理新输入，得到中间状态，记为 H₂₀。后半段用于读取全文的全局 KV，直接用 H₂₀ 乘相应的投影权重得到。以第 30 层为例：

传统路径：
H₂₀
↓
完整计算第 21～29 个 Block
↓ 得到第 29 层结果
投影出第 30 层的全局 KV

CED 路径：
H₂₀
↓ 第 30 层的投影权重
第 30 层的全局 KV

投影这一步仍然要算。不过，从 H₂₀ 算出后半段需要的全局 KV，比跑完后 20 个 Block 少了许多工作。

后半段各层可以使用不同的投影权重，但都能从 H₂₀ 出发。为了准备这些全局 KV，原本还要在历史位置上执行的第 21、22 层等后续层的 Attention、FFN，就能省下。

这样，为这 2000 个新 token 准备全局 KV 时，就不用让每个位置都完整跑过后半段。

KV Cache → 算过的，不重复算
MLA → 每份历史记录，存小一点
CED → 准备新记录时，少跑完整层

少跑的是输入 KV 计算，不是答案生成

那后 20 个 Block 还在干什么？

读入工具结果时，大部分位置只需要准备好供后面读取的 KV。等到生成答案，当前 token 仍会经过完整网络：

当前 token
↓
前 20 个 Block
↓
后 20 个 Block
↓
预测下一个 token

后半段各层仍会生成自己的查询，读取历史 KV，再继续加工当前 token。

省下的是读入长输入时的那部分计算。生成答案时，40 个 Block 仍然都要跑。

快了，代价是什么？

原来，深层的全局 KV 来自一路加工到该层的历史状态。现在，后半段的全局 KV 都从第 20 层结果出发，再用各层的权重变换，或者跨层复用。

后半段仍能继续处理当前 token，但它读取的全局 KV，少了原来那些逐层加工历史内容的计算。跨层复用又让一些层共用 KV，低精度存储则会引入数值误差。这些改动都需要模型在训练中适应。

DeepSeek 报告称，CED 能让 Prefill 计算接近减半，性能与基线相当。

回到修 Bug 的 Agent：工具返回的 2000 个新 token，第一次进入模型时，少跑一部分完整层计算；算出的 KV 再通过复用和低精度存储，减少保存和读取的开销。

所以，看 Agent 的快慢，除了每秒生成多少 token，也要看工具返回之后，它要花多久才能接着干活。
