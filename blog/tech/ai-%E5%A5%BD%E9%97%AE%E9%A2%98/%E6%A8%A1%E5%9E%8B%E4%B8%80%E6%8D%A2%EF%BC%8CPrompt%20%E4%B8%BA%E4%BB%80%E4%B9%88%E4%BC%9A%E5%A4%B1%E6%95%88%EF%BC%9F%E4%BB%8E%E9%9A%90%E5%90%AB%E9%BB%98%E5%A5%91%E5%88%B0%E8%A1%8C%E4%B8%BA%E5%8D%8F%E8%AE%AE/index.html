Prompt 没变，为什么换个模型，行为就变了？

假设我们做了一个技术简报助手。

输入五篇资料，它负责写一篇 500～800 字的中文简报。Prompt 很普通：

你是一名严谨、专业的技术编辑。

请阅读以下资料，写一篇 500～800 字的中文技术简报。
要求内容准确、表达自然，并给出有依据的判断。

它稳定运行了一段时间。事实基本准确，遇到互相矛盾的资料，也知道把分歧留下来。

后来模型升级了。

新模型写得明显更顺，标题也更像人写的。可仔细一看，两个来源原本还在争论，它却替双方总结出了一个确定答案；有个数字只在营销稿里出现，它也顺手写进了结论。

Prompt 一个字没改，文章甚至更好看了，任务却做坏了。

文章更好看了，为什么反而错了？

问题藏在“严谨”“专业”“有依据”这些听起来很清楚的词里。

严谨，是每句话都附来源，还是只采用可信来源？两个来源冲突时，是选择看起来更权威的一方，还是把分歧交给读者？所谓有依据，是允许根据常识补全，还是只能使用给定资料？

Prompt 没说。

旧模型比较保守，碰到冲突时停了下来。新模型更擅长组织材料，为了让文章完整、流畅，主动替我们消解了冲突。它们都可以认为自己在“给出有依据的判断”。

这类失效很难第一时间发现。它不报错，也不胡言乱语，甚至显得更聪明。它只是悄悄换了一种方式，理解我们从未明说的要求。

过去表现稳定，不一定说明 Prompt 写对了。也可能只是旧模型碰巧猜对了我们的默契。

Prompt 没变，解释它的人变了

我们很容易把 Prompt 当成程序：只要文字不动，行为就应该不动。

如果一定要用程序来比喻，Prompt 更像一段需要解释的脚本。模型不只负责执行，还在决定每句话究竟是什么意思。更换模型，相当于连解释器和默认设置一起换了。

真正决定结果的是：

最终行为 = Prompt + 模型 + 上下文 + 参数

Prompt 只是其中一项。模型一换，解释任务的方式也换了。

所以模型升级后 Prompt 失效，往往不是那几句话突然过期了。新模型只是用不同的回答，把藏在 Prompt 空白处的问题暴露了出来。

这也解释了一个常见现象：遇到跑偏，我们总想把语气写得更重。

你是一名极其严谨、客观、专业、善于核验事实的资深技术专家。

但“极其严谨”并没有比“严谨”多规定一个动作。模型要猜的事情，一件也没少。

把默契一条条抓出来

改法就藏在那篇做坏了的简报里。

它替两个冲突来源下了结论，我们就把这条默契写出来：

如果两个来源互相矛盾，且现有资料无法消除冲突，
保留双方说法，不得自行选择一方作为事实。

再跑一次。冲突保住了，可资料里缺少一个关键数字，模型又根据上下文补了个“大概”。于是再加一条：

如果资料中找不到相关信息，不要自行补全。
缺失信息会影响结论时，缩小结论并说明缺失。

最后，事实和判断偶尔还会混在一起，我们干脆规定输出结构：

正文依次包含：

已知事实
尚存分歧
我的判断

到这里，Prompt 的变化很有意思。

最初，我们在描述一个理想的助手：你要严谨、专业、准确。

现在，我们在描述任务本身：遇到什么情况，采取什么动作；规则冲突时谁优先；信息不够时在哪里停下来。

“不要胡编乱造”是一种期望。“找不到依据时，不补全并说明缺失”才是一种可以观察的行为。

Prompt 的稳定性，往往就藏在这一步里：少描述性格，多交代边界。

有些规则不该继续写进 Prompt

改到这里，新模型稳定了不少。但第三次发现它漏掉“尚存分歧”时，我们终于没有再往 Prompt 里补一句“必须严格遵守”。

自然语言里的“必须”，终究还是一句需要模型理解的自然语言。既然区块缺没缺、篇幅超没超都能直接检查，为什么还要每次提醒模型？

简报助手于是多了一道关：模型负责阅读和判断，程序负责守住确定的边界。

五篇资料
    ↓
行为明确的 Prompt
    ↓
模型生成简报
    ↓
检查结构与来源
    ↓
通过 / 重试 / 拒绝输出

输出格式可以交给 Schema，篇幅可以由程序计算，关键数字有没有标注来源也可以检查。至于来源是否真的支持这个数字、资料之间是否存在分歧，仍然需要模型判断。

这里没有必要把模型管得更死。需要理解的，留给模型；能够确定验证的，就别再赌模型这次愿不愿意照做。

越不能出错的规则，越不该只写在 Prompt 里。

模型会换，应该留下什么？

现在再问：有没有一套 Prompt，可以从当前模型一直用到未来所有模型？

很难有。

只要规则仍由自然语言表达，它就需要被解释；只要模型还会升级，解释方式就可能变化。能留下来的，是我们从失败中抓出来的东西：什么算完成，什么算越界，碰到分支怎么办，结果如何检查。

所谓 Prompt 迭代，也就不再是把同一句要求越写越重。每失败一次，我们都多发现了一条原先没意识到的业务规则，再决定它应该写进 Prompt，还是交给程序检查。

从这个角度看，换模型像一次意外的压力测试。那些一升级就消失的“稳定表现”，原来并不属于系统，只是暂时寄存在旧模型的习惯里。

模型可以换，文风和判断倾向也可以变。只要任务边界没有跟着悄悄漂走，升级就不必等于重写一切。

不过，故事到这里还没结束。

为了修复前面的失败，Prompt 已经从 v1 改到了 v5。v5 在这五篇资料上表现更好，换一批资料，却可能还不如 v3。如果最后仍靠“读起来不错”挑版本，我们和最开始凭感觉写下“请保持严谨”，其实没有走出多远。

Prompt 工程的下一步，可能不是写出 v6，而是先找一把不会跟着模型一起漂移的尺子。
