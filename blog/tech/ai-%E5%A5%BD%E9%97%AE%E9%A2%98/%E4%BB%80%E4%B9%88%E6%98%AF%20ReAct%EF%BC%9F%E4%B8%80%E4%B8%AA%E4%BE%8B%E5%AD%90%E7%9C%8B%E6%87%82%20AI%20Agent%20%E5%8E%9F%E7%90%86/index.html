什么是 ReAct？一个例子看懂 AI Agent 原理

Agent 不是一种神秘技术。

如果把各种框架（LangGraph、AutoGen、OpenAI Agents SDK、CrewAI……）全部去掉，你会发现：

Agent = LLM + 循环（Loop）+ 工具（Tool）+ 状态（State）

这篇文章，我们不用任何框架。从一个只有十几行代码的小例子开始，一步一步把 Agent 演化出来。

咱依旧从天气的例子开始

第一阶段：普通 LLM，其实不是 Agent

先看最普通的调用。

from openai import OpenAI

client = OpenAI()

response = client.responses.create(
    model="gpt-4.1",
    input="北京今天天气怎么样？"
)

print(response.output_text)

整个流程非常简单：

用户
   │
   ▼
Prompt
   │
   ▼
LLM
   │
   ▼
Answer

特点只有一个：

输入一次，输出一次。

模型不知道：

  • 有没有工具
  • 能不能查询天气
  • 是否需要继续执行

它只是回答。

例如：

抱歉，我无法获取实时天气。

这就是普通 Chat。

距离 Agent 还差得远。

第二阶段：给 LLM 一把工具

如果告诉模型：

你可以调用一个天气函数。

例如：

def get_weather(city):
    return "北京：26℃，晴"

然后告诉模型：

你有一个工具：

get_weather(city)

需要天气时，请调用它。

这时候很多模型都会返回：

{
    "tool": "get_weather",
    "args": {
        "city": "北京"
    }
}

注意。

这里工具其实还没执行。

LLM 只是说：

我建议调用这个工具。

所以目前流程变成：

用户
   │
   ▼
LLM
   │
   ▼
告诉程序：
调用 get_weather

模型只是一个"决策者"。

真正执行工具的是你的程序。

第三阶段：程序替模型执行工具

于是程序开始多一步。

tool_call = llm(prompt)

result = get_weather(tool_call["city"])

print(result)

流程变成：

用户
 │
 ▼
LLM
 │
 ▼
Tool Call
 │
 ▼
Python
 │
 ▼
执行工具
 │
 ▼
结果

例如：

get_weather("北京")

得到：

北京：26℃

但是问题来了。

程序拿到了天气。

模型不知道。

因为天气是在 Python 世界发生的。

模型根本没看见。

第四阶段：把工具结果再喂回模型

所以需要第二次调用。

第一次：

LLM：

调用 get_weather("北京")

Python：

北京：26℃

第二次：

LLM：

工具返回：

北京：26℃

请继续回答用户。

于是模型输出：

北京今天26℃，天气晴朗。

整个流程：

第一次

用户
 │
 ▼
LLM
 │
 ▼
Tool Call

↓

Python执行

↓

第二次

LLM
 │
 ▼
最终回答

到这里，已经越来越像 Agent 了。

但是还有问题。

第五阶段：如果需要多个工具怎么办？

例如：

用户说：

上海天气怎么样？

顺便告诉我美元汇率。

模型第一次返回：

调用：

get_weather()

程序执行。

得到：

天气……

再次发给模型。

模型又说：

调用：

get_exchange_rate()

程序继续执行。

得到：

7.16

再次发回模型。

模型最后回答：

上海今天……
美元汇率……

发现了吗？

出现了一个新东西。

循环。

程序开始不断：

LLM

↓

Tool

↓

LLM

↓

Tool

↓

LLM

↓

……

直到：

模型说：

没有工具要调用了。

循环结束。

第六阶段：真正的 Agent Loop 出现了

于是代码开始变成经典写法。

messages = [user_message]

while True:

    response = llm(messages)

    if response.need_tool():

        result = call_tool(response)

        messages.append(result)

    else:

        print(response.text)
        break

注意。

整个 Agent 最核心的东西，就是这个 while。

很多框架绕来绕去。

最后都会落到类似逻辑。

while True

    问 LLM

    如果要工具：

        调工具

        放回上下文

    否则：

        结束

Agent 的生命，就来自这个循环。

第七阶段：为什么需要 State（状态）？

继续思考。

如果只有：

response = llm(prompt)

第二次调用的时候：

模型已经忘了第一次发生什么。

所以 Agent 必须保存历史。

例如：

messages = [
    {
        "role": "user",
        "content": "北京天气"
    }
]

调用工具以后：

messages.append(
    {
        "role": "tool",
        "content": "26℃"
    }
)

再次调用：

response = llm(messages)

模型现在看到的是：

User：

北京天气

↓

Tool：

26℃

于是它知道：

哦，我已经查过天气了。

这就是 Agent 的 State。

State 本质就是：

让模型记住已经发生过什么。

第八阶段：为什么 Agent 可以规划？

继续升级。

例如：

帮我分析苹果股票。

如果上涨，
看看新闻；

如果下跌，
看看财报。

模型第一次可能输出：

Step1：

查询股价

Python执行。

回来。

模型继续：

Step2：

查询新闻

回来。

模型继续：

Step3：

总结

你会发现。

没有任何地方写：

第一步……
第二步……
第三步……

全部都是模型自己决定。

所以：

Agent 并不是程序会规划。

真正规划的是：

LLM。

程序只是一直：

执行

↓

反馈

↓

执行

↓

反馈

第九阶段：再加一个 Memory

如果每次聊天：

messages=[]

模型都会忘记以前内容。

于是增加：

memory = []

memory.append(user)

memory.append(tool)

memory.append(ai)

下一次：

response = llm(memory)

于是：

Agent 开始有了长期记忆。

很多所谓：

  • Memory
  • Long Context
  • RAG
  • Vector Database

本质都是：

帮助模型恢复 State。

第十阶段：完整的极简 Agent

最后，把所有东西拼起来。

messages = []

while True:

    response = llm(messages)

    if response.has_tool_call():

        result = call_tool(response.tool)

        messages.append(result)

    else:

        print(response.text)
        break

while True:

    response = llm(messages)

    if tool_call:

        result = tool()

        messages.append(result)

    else:

        break

代码不到二十行。

却已经包含了 Agent 最重要的几个组成部分。

Agent 的本质，其实只有四个组件

很多人第一次接触 Agent，会觉得它是一种全新的 AI 技术。

实际上，如果把各种框架和工程细节剥离掉，Agent 的核心非常简单：

          +----------------+
          |      LLM       |
          +-------+--------+
                  |
          判断下一步做什么
                  |
                  v
        +------------------+
        |     Tool Call    |
        +--------+---------+
                 |
            执行真实操作
                 |
                 v
        +------------------+
        |      State       |
        +--------+---------+
                 |
          更新上下文信息
                 |
                 v
        +------------------+
        |      Loop        |
        +------------------+
                 |
          继续问 LLM？

四者缺一不可：

  • LLM：负责思考、规划和决策。
  • Tool：负责与外部世界交互，例如搜索、数据库、API、文件系统等。
  • State：记录已经发生的事情，让模型拥有上下文，而不是每一步都从零开始。
  • Loop：不断执行"思考 → 工具 → 更新状态 → 再思考"，直到任务完成。

可以把它总结成一句话：

Agent 并不是一种新的模型，而是在 LLM 外面包了一层能够持续决策、调用工具和维护状态的执行循环。

理解了这四个组件，再去看 LangGraph、OpenAI Agents SDK、CrewAI 或 AutoGen 等框架，会发现它们做的事情其实高度一致：只是把这套循环封装得更完善、更易扩展而已。真正的 Agent 原理，并没有想象中复杂。
