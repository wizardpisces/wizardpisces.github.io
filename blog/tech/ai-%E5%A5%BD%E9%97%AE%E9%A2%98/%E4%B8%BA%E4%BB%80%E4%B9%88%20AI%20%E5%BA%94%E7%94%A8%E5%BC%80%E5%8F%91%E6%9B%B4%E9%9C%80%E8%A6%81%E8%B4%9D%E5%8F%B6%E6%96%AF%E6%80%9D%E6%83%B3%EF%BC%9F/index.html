为什么 AI 应用开发更需要贝叶斯思想？

AI 应用研发比传统软件研发更需要贝叶斯决策思想。原因不是 AI 更复杂，而是 AI 产品的不确定性远高于传统软件。

传统软件实现的是确定需求：

用户点击按钮 → 后端计算 → 返回结果。

AI 应用在不断验证概率问题：

  • 用户真的需要这个能力吗？（需求不确定）
  • Prompt 是否有效？（方案不确定）
  • Model A 还是 Model B 更好？（模型不确定）
  • Agent 是否应该拆成多个工具？（架构不确定）
  • 用户为什么满意或不满意？（反馈不确定）

研发过程就是不断更新这些概率。

贝叶斯思想的核心公式是：

‌后验概率 ∝ 先验概率 × 似然‌

翻译成产品语言就是：

‌更新后的判断 ∝ 之前的判断 × 新观察到的证据

以下通过几个例子说明这个现象

例子一：AI Router

用户输入一句话：

帮我总结这份 PDF。

系统并不知道应该调用哪个模型。

开始时，它只是猜：

belief = {
    "gpt-4.1": 0.4,
    "claude": 0.4,
    "gemini": 0.2
}

跑了一千次。

发现：

  • PDF 总结，Claude 最稳定。
  • 数学推理，GPT 更好。
  • 图片理解，Gemini 更好。

Router 变成：

belief = {
    "gpt-4.1": 0.2,
    "claude": 0.7,
    "gemini": 0.1
}

它不是在寻找唯一正确答案。

而是在不断调整：

什么情况下，更应该相信哪个模型。

例子二：RAG

用户问：

MCP 是什么？

第一次检索：

Doc A  相似度 0.82
Doc B  相似度 0.79
Doc C  相似度 0.74

系统觉得：

Doc A 最可能有帮助。

回答以后用户立刻追问：

不是，我说的是 Anthropic 的 MCP。

系统突然发现原来自己的判断错了。

于是下一次遇到：

MCP

它开始提高 Anthropic 文档的权重。

降低其他 MCP 文档。

这里更新的不是答案。而是：

哪类文档更值得相信。

例子三：Agent Tool Selection

Agent 有三个工具：

Search
Python
Browser

收到请求：

帮我统计 Excel。

开始：

Search  40%
Python 35%
Browser 25%

执行几十轮。

发现Excel 请求几乎都调用 Python。

慢慢变成：

Search  5%
Python 90%
Browser 5%

整个 Agent 的行为改变了。

没有改 Prompt。

没有改模型。

只是：

相信 Python Tool 的概率越来越高。

为什么 AI 特别需要这种思维

AI 系统本身就是概率系统：

  • LLM：P(next token | context)
  • RAG：P(这篇文档有帮助)
  • Embedding：P(语义相似)
  • ReRank：P(应该排第一)
  • Agent：P(应该调用哪个 Tool)
  • Evaluation：P(用户满意)

整个 AI Pipeline 到处都是概率。 AI 产品研发自然应该采用不断根据证据更新判断的方法，而不是一次性做出不可更改的决策。

优秀 AI 团队真正更新的不是代码，而是"信念"

提出假设（Prior）
        ↓
做最小可验证版本（MVP）
        ↓
收集真实用户行为（Evidence）
        ↓
更新产品判断（Posterior）
        ↓
重新分配研发资源
        ↓
提出新的假设

代码只是实验载体，真正持续迭代的是团队对"什么最有价值"的信念。AI 产品由于需求、模型能力和用户行为都具有高度不确定性，因此比传统软件更依赖这种基于证据持续更新决策的研发方式。
